# AGENTS.md

## Cursor Cloud specific instructions

This is a Python (Streamlit) multi-property hotel/rental rate-management tool. General setup, usage, and architecture are documented in `readme.md`. The notes below are durable, non-obvious caveats for working in the cloud environment.

### Environment
- Python deps live in a project-root virtualenv at `venv/`. The update script creates it and installs `requirements.txt`. Several scripts (e.g. `scripts/run_morning_data_pipeline.py`, `scripts/run_morning_data_pipeline.sh`) hard-depend on `venv/bin/python` and re-exec into it, so the venv MUST be at the repo root and named `venv`.
- Run Python via `./venv/bin/python ...` (or `source venv/bin/activate`).

### Required secret
- `PRICELABS_API_KEY` is **required at import time**, not just at call time: `rates/config.py` raises `ValueError` if it is unset, and that module is imported transitively by the Streamlit app (`app/app_2.py`) and the data pipeline. Without it, the app and pipeline fail to even start. It is provided as a runtime secret/env var. `API_BASE_URL` and `LOG_LEVEL` are optional (sane defaults in `rates/config.py`).

### Running the app (primary product)
- `./venv/bin/python -m streamlit run app/app_2.py --server.port 8501 --server.address 0.0.0.0 --server.headless true --server.enableCORS false --server.enableXsrfProtection false`
- Serves on port 8501. Core flow: select property → "Generate Rates" → review/edit rates in the grid. Generating rates pulls/derives data and can take ~10-30s.

### CLI pricing engine
- `./venv/bin/python run_pricing.py --property <key>` (keys are the `data/<key>/` dirs, e.g. `atx1`). Writes to `output/`. This path does NOT call the live API (uses local data files).

### Morning data pipeline — live API, mutating
- `./scripts/run_morning_data_pipeline.sh` hits the **live PriceLabs API**. A full run: (1) regenerates `pl_daily` for all 9 properties (long — ~15-20 min of API calls), (2) pulls nightly overrides, (3) runs the rules adjuster and **pushes live rate overrides** to PriceLabs for `onera`, `wb1`, `flo1`.
- Use `--dry-run` to exercise steps 1-3 without pushing live rates (safe for verification). Use `--rules-push-only` to skip the long data-generation steps and only run the rules step.
- Summaries are written to `logs/morning_data_pipeline_summary.txt` and `logs/rules_adjuster_automation_summary.txt`. The pipeline emits verbose `🔍 DEBUG:` lines to stdout — this is normal, not an error.

### Gotchas
- Do not pipe long-running pipeline output through `tail`/`tee`-less buffering when you need live progress; `tail` buffers until completion. Redirect to a `logs/*.log` file and poll it, or watch `logs/generate_all_properties_summary.txt` which updates per-property.
- Most generated/pulled data files under `data/*/` and everything under `logs/` are git-ignored and regenerated by the pipeline.
